## 0. 先说一个 bug

上线前一天，我发现程序把一份 **¥4.50 的薯条**显示成了 **¥450.00**。

不是小数点错了，是我自作聪明：

```python
def money(value):
    number = float(value)
    if number > 1000:        # 「金额超过 1000，那肯定是分」
        number /= 100
    return f"¥{number:.2f}"
```

这个启发式对 ¥114.50（接口返回 `11450`）工作得很好，直到遇上 ¥4.50（接口返回 `450`）——`450` 不大于 1000，于是被当成「元」原样输出。

**教训：单位是接口契约的一部分，永远不要靠数值大小去猜。** 后面所有的坑，本质上都是同一类问题：**文档没写，但接口有脾气。**

这篇文章把这 7 个坑和盘托出。如果你也打算接这套 MCP，可以直接跳过调试阶段。

## 2. 七个坑速查表

给跳读的同学，细节在后面：

| # | 坑 | 一句话解法 |
| --- | --- | --- |
| ① | 金额单位是「分」，但个别字段是「元」字符串 | 显式转换，禁止猜单位 |
| ② | `query-meals` 只返回编码和标签，没有名称价格 | 用 `calculate-price` 批量补全 |
| ③ | 套餐改配定价协议要自己逆向 | 回传**完整** `roundList`，`round` 是字符串 |
| ④ | 菜单类工具必须「门店前置」 | 先解析门店，再传 `storeCode/orderType/beType` |
| ⑤ | `beCode` 传不传，取决于 `beType` | 1 不能传，2/5/6 必须传 |
| ⑥ | 营养数据是一整段紧凑表格字符串 | 自己写解析器，注意餐品名对不上 |
| ⑦ | 真实菜单里混着非餐品 | 推荐前先排除蘸酱和周边 |

## 3. 坑 ①：金额单位是「分」，但有的字段是「元」

`calculate-price` 返回 `11450`，意思是 **¥114.50**。但 `order-list` 里的 `realTotalAmount` 是字符串 `"13.9"`，积分字段也是字符串 `"192.6"`。

**同一个接口体系里，两种单位，三种类型（int / str / 元 / 分）。**

现在的写法是让单位在函数名里说清楚，绝不猜：

```python
def cents_to_yuan(value: Any) -> float:
    """麦当劳 MCP 的金额单位是「分」，转换为「元」。"""
    try:
        return round(float(value) / 100, 2)
    except (TypeError, ValueError):
        return 0.0


def money(value: Any) -> str:
    """把「元」数值格式化为 ¥x.xx。本函数不做任何单位猜测。"""
    try:
        return f"¥{float(value):.2f}"
    except (TypeError, ValueError):
        return "—"
```

调用方必须显式选择用哪个：

```python
money(cents_to_yuan(price_cents))     # 分 → 元
money(row["realTotalAmount"])          # 本来就是元字符串
```

> **顺带一提**：还有第三个坑——所有工具返回统一信封 `{success, code, message, datetime, traceId, data}`，
> 业务数据藏在 `data` 里，`success=false` 时 `data` 直接不存在。这个要统一收口，不然每个调用点都要写一遍防御代码：
>
> ```python
> def unwrap(payload: Any, tool: str = "") -> Any:
>     """拆开响应信封，返回 data；失败时抛出 MCDApiError。"""
>     if not isinstance(payload, dict):
>         return payload
>     if payload.get("success") is False:
>         code = payload.get("code", "")
>         message = payload.get("message", "未知错误")
>         raise MCDApiError(f"[{tool}] {message}" + (f"（code={code}）" if code else ""))
>     return payload.get("data", payload)
> ```

## 4. 坑 ②：`query-meals` 只给你编码，不给名称和价格

这是最容易卡住的一步。`query-meals` 的返回结构长这样：

```json
{
  "categories": [
    {
      "name": "汉堡",
      "meals": [{ "code": "9900013304", "tags": ["100%纯牛肉", "人气热卖"] }]
    }
  ]
}
```

**没有名称，没有价格，只有 `code` 和一点 `tags`。**

要拿到可读菜单，必须再调 `calculate-price` 批量补全：

```python
async def enrich_menu(client, store_code, items, chunk_size: int = 50):
    """用 calculate-price 批量补全菜单的名称与价格。"""
    price_map: dict[str, tuple[str, float]] = {}

    async def price_batch(batch):
        if not batch:
            return
        args = _store_args(store_code, ORDER_PICKUP, BE_DINE_IN)
        args["items"] = [{"productCode": i.code, "quantity": 1} for i in batch]
        try:
            data = unwrap(await client.call("calculate-price", args), "calculate-price")
        except MCDApiError:
            if len(batch) == 1:
                return                      # 单个商品不可售，跳过
            mid = len(batch) // 2           # ← 二分重试
            await price_batch(batch[:mid])
            await price_batch(batch[mid:])
            return
        for row in (data or {}).get("productList", []):
            code = str(pick(row, "productCode", default=""))
            price_map[code] = (
                str(pick(row, "productName", default="")),
                cents_to_yuan(pick(row, "subtotal", "originalSubtotal", default=0)),
            )

    for start in range(0, len(items), chunk_size):
        await price_batch(items[start : start + chunk_size])
    # 把 name / price 回填到 items ...
```

两个实战提醒：

1. **一次别传太多。** 我按 50 个一批切块，并且对失败的分块做**二分重试**——某一块炸了不会拖垮整个菜单，最多降级成「这一个商品没有价格」。
2. **`tags` 比名称有用得多。** 菜单名是人看的，`tags` 才是机器能用来做匹配的（后面第 8 节会讲为什么）。

## 5. 坑 ③：套餐改配的定价协议，得自己逆向

这是整个项目里最费劲、也最有意思的部分。

套餐的组成是 `rounds[].choices[]`，每个 choice 带 `isDefault` 和 `diffPrice`：

```json
{
  "rounds": [
    {
      "round": "1",
      "name": "选择汉堡",
      "choices": [
        { "code": "520001", "name": "麦辣鸡腿汉堡", "isDefault": true,  "diffPrice": "+ ¥0" },
        { "code": "520002", "name": "板烧鸡腿堡",   "isDefault": false, "diffPrice": "+ ¥1.5" }
      ]
    }
  ]
}
```

想算「改配之后多少钱」，**必须回传完整的 `roundList`**——每一轮都要有，不能只传改动的那一轮。而且：

- `round` 是数字 id 的**字符串**形式（`"1"` 而不是 `1`）
- 只能选**真实存在**的 code，编一个直接报错

价格公式是：

```
新价 = 套餐价 + Σ(diffPrice × 该轮数量)
```

我用真实数据验证过这条链路，四个点是自洽的：

```
11450  →  11800  →  11950  →  12300
（原价）  （+¥3.5） （+¥1.5） （+¥3.5）
```

**关键认知：价格不是算出来的，是问出来的。** 我的实现里从来不用公式自己算，而是把 `roundList` 回传给 `calculate-price`，让门店实时核价——公式只用来做单元测试的断言。

这一点在产品上也很有价值：用户改了配方，看到的价格是**门店真的会收的钱**，不是估算。

## 6. 坑 ④⑤：门店前置 与 `beCode` 的薛定谔状态

**菜单 / 价格 / 优惠券类工具，全部必须先有门店。** 没有 `storeCode` 什么都干不了。所以流程永远是：

```
定位城市 → query-nearby-stores → 选门店 → 才能拉菜单
```

然后是两个参数：

```python
BE_DINE_IN   = 1   # 到店取餐
BE_DELIVERY  = 2   # 麦乐送到家
BE_DRIVE_THRU = 5  # 得来速
BE_GROUP     = 6   # 企业团餐

NEEDS_BE_CODE = {BE_DELIVERY, BE_DRIVE_THRU, BE_GROUP}
```

- `beCode` 在**到店自取（`beType=1`）时不能传**，传了报错
- 在**外送 / 得来速 / 团餐（2/5/6）时必须传**，不传报 `600048「外送场景下，beType=2/5/6时必传beCode」`
- 而 `beCode` 本身要先去 `delivery-query-stores` 拿，那个接口又需要先有地址 ID

收口成一个函数，调用方就再也不用记这些：

```python
def _store_args(store_code, order_type, be_type, be_code="") -> dict:
    args = {"storeCode": store_code, "orderType": order_type, "beType": be_type}
    if be_type in NEEDS_BE_CODE and be_code:
        args["beCode"] = be_code      # 只在该传的时候传
    return args
```

**还有一个很坑的小细节**：`query-nearby-stores` 的 `city` 和 `keyword` **必须同时非空**，只传一个会返回 `600058「城市名或者关键词不能为空」`。也就是说你没法只按城市列出所有门店——必须带个关键词（我默认填「麦当劳」）。

## 7. 坑 ⑥：营养数据是一整段紧凑表格字符串

`list-nutrition-foods` 不返回 JSON 数组，返回的是**一段字符串**：

```
[160]{productName,nutritionDescription,energyKj,energyKcal,protein,fat,carbohydrate,sodium,calcium}:
  猪柳麦满分,null,1288,308,16,16,24,781,213
  巨无霸,null,2146,513,25,26,46,940,180
```

而且——**餐品名和菜单对不上**：菜单叫「麦辣鸡翅2块」，营养表叫「麦辣鸡翅-2块」。

所以要做两件事：

```python
_NUTRIENT_KEYS = ("energyKj", "energyKcal", "protein", "fat", "carbohydrate", "sodium", "calcium")


def parse_nutrition_table(payload) -> dict[str, dict]:
    """解析 list-nutrition-foods 返回的紧凑表格字符串。"""
    header_match = re.search(r"\{(.*?)\}", payload)
    columns = [c.strip() for c in header_match.group(1).split(",")]
    body = payload[header_match.end():]

    table = {}
    for line in body.split("\n"):
        cells = [c.strip() for c in line.split(",")]
        if len(cells) < len(columns):
            continue
        row = dict(zip(columns, cells, strict=False))
        name = row.get("productName", "").strip()
        if not name:
            continue
        table[name] = {"name": name} | {k: to_float(row.get(k)) for k in _NUTRIENT_KEYS}
    return table
```

外加一层**名称归一化**（去掉 `-`、空格、`（`/`(` 差异），才能把菜单和营养表对上。

> 这里有个副产品：解析出来的营养表其实是一份「麦当劳全菜单营养成分数据库」，
> 隐藏菜单实验室的「减脂版」对比就是靠它算出来的（2142 kcal → 1220 kcal）。

## 8. 坑 ⑦：真实菜单里混着非餐品

这个坑不是技术问题，是**产品问题**，但我觉得比前面几个都更值得说。

我做了个「团餐指挥官」：输入每个人的预算 / 口味 / 忌口，自动合成一份团餐。第一版逻辑很简单——**预算内取最便宜的**。

结果它给预算 ¥25 的人推荐了 **¥2.00 的饼干**。

因为真实菜单里混着这些：

| 分类 | 里面的「非餐品」 | 价格 |
| --- | --- | --- |
| 小食甜品 /其他 | 麦当劳素龙限定饼干 | ¥2.00 |
| 小食甜品 /其他 | 「葱不求人」按摩捶痒痒挠 | ¥14.90 |
| 蘸酱炸鸡 | 韩式烟熏芝士风味酱 | ¥3.00 |
| 蘸酱炸鸡 | 蘸酱韩式甜辣酱鸡块 | ¥11.90 |

**约束全满足，但没人会这么点单。**

这就是「满足约束」和「像人话」的差别。改成三步：

```python
def _match(menu, person):
    if not menu:
        return None

    # 1. 忌口优先，一票否决
    candidates = [m for m in menu if not any(_hit(m, bad) for bad in person.avoid)]
    if not candidates:
        candidates = list(menu)

    # 2. 排除非餐品（蘸酱、周边、玩具、礼品卡…）
    meals = [m for m in candidates if _is_meal(m)]
    if meals:
        candidates = meals

    # 3. 口味命中
    if person.want:
        wanted = [m for m in candidates if _hit(m, person.want)]
        if wanted:
            candidates = wanted

    # 4. 预算内取「最接近预算」的那份，而不是最便宜的
    target = person.budget or DEFAULT_TARGET
    if person.budget:
        within = [m for m in candidates if m.price <= person.budget]
        if within:
            return _best_value(within, target)
    return _best_value(candidates, target)
```

`_best_value` 的排序键是 `(_meal_tier(m), -abs(m.price - target), m.price)`——**先看是不是正经餐品，再看离预算多近，最后才比绝对价格。**

### 顺便说一个特别隐蔽的 bug

「巨无霸」这个名字里**没有「堡」字**。

我原来用「名字里有没有『堡/卷/饭』」来判断是不是主食，于是 ¥24.50 的巨无霸被归类成「小食」，排在 ¥9.90 的吉士汉堡包后面。

修法是**先看分类、再看名字**：

```python
_DRINK_HINTS = ("饮", "咖啡", "可乐", "雪碧", "牛奶", "果汁", "红茶")
_MAIN_CATEGORY_HINTS = ("堡", "餐", "卷", "饭", "随心配", "乐园", "大卡", "人气热卖")
_MAIN_NAME_HINTS = ("堡", "卷", "餐", "随心配", "饭")


def _meal_tier(item) -> int:
    """2 = 主食/套餐，1 = 小食/炸鸡，0 = 饮品。"""
    if any(h in item.category for h in _DRINK_HINTS) or any(h in item.name for h in _DRINK_HINTS):
        return 0
    if any(h in item.category for h in _MAIN_CATEGORY_HINTS):   # ← 分类优先
        return 2
    if any(h in item.name for h in _MAIN_NAME_HINTS):
        return 2
    return 1
```

分类是接口给的，比名字可靠得多。这个 case 我专门留了一条回归测试，测试名就叫「巨无霸不能被当成小食」。

### 还有标签的否定语义

`tags` 里有 `100%纯牛肉` 这种长营销词，也有 `无咖啡因` `非油炸` 这种否定式。

- 用**精确相等**匹配 → `牛肉` 匹配不上 `100%纯牛肉`
- 用**子串**匹配 → `油炸` 会错误命中 `非油炸`

最后是子串匹配 + **否定词前置判定**：

```python
_NEGATION_HINTS = ("无", "非", "不含", "零", "去")


def _is_negated(tag: str, keyword: str) -> bool:
    """关键词在标签里是否被否定（「无咖啡因」对「咖啡」是否定）。"""
    index = tag.find(keyword)
    if index <= 0:
        return False                    # 关键词就在开头，不算被否定
    prefix = tag[:index]
    return any(hint in prefix for hint in _NEGATION_HINTS)
```

否定词必须出现在关键词**之前**才算数，这样 `无咖啡因` 不会命中 `咖啡`，但 `咖啡` 本身依然能被匹配到。

## 9. 怎么保证「离线演示」和「线上」不跑偏

这个项目有一个 `--demo` 模式，不需要 Token 就能跑全流程。它存在的意义是：**让别人 clone 下来 30 秒就能看到效果，不用先去申请 Token。**

但离线数据最大的风险是**和线上行为漂移**——demo 里 `roundList` 校验很松，线上很严，用户就会在切到真实接口时踩坑。

所以我做了两件事：

1. **demo 和线上共用同一条代码路径。** `--demo` 只是把 MCP client 换成一个假的实现，业务层、解析层、展示层完全一样。
2. **用测试锁死保真度。** `tests/test_demo.py` 专门断言「演示数据的结构和真实响应的结构一致」。

甚至连错误码都复刻了：

```python
# demo.py
return _fail(600048, "外送场景下，beType=2/5/6时必传beCode")
return _fail(600058, "城市名或者关键词不能为空")
```

这样 CI 里**不用 Token 也能跑全量测试**（187 个，全绿）。

顺带一提，这个假 client 还让「瞬时故障重试」变得可测——我 monkeypatch 掉 `asyncio.sleep`，就能断言退避序列确实是 `[0.8, 1.6]`：

```python
def test_backoff_is_exponential(self, no_sleep):
    """连续抖动时，等待时间应为 0.8 → 1.6 指数退避。"""
    client, session = make_client([
        RuntimeError("429 Too Many Requests"),
        RuntimeError("503 Service Unavailable"),
        _FakeResult({"success": True, "data": {}}),
    ])
    run(client.call("query-meals", {}))
    assert session.calls == 3
    assert no_sleep == [0.8, 1.6]
```

## 11. 一些刻意的取舍

**只查不改。** 项目没有实现下单、取消订单、抽奖、积分商城——虽然这些工具都在。涉及钱和积分的操作，我全部留给用户自己去官方 App 完成。这不是「做不了」，是「不该由一个第三方助手代劳」。

**不确定的地方要说出来。** 拿不到数据 ≠ 数据是 0。某个人的需求没被满足，我会在输出里写一条 `⚠️ 匹配说明`，而不是静默吞掉。

```python
⚠️ 匹配说明：
  · **小张**：超预算 ¥2.50
```

**Token 绝不落盘。** 配置只走环境变量，仓库里做密钥扫描。
