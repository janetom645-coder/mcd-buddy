**标题**：给麦当劳 MCP 写了个助手，顺便把真实接口的坑全踩了一遍

**正文**：

麦当劳中国最近开放了官方 MCP（`https://mcp.mcd.cn`，35 个工具，Streamable HTTP），我基于它写了个多玩法助手「麦门四重奏」。四个玩法是壳，真正花时间的是把接口对齐。

几个反直觉的坑，分享一下：

**① 金额单位是「分」，但有的字段是「元」**
`calculate-price` 返回 `11450` = ¥114.50。但 `order-list` 的 `realTotalAmount` 是字符串 `"13.9"`，积分字段也是字符串 `"192.6"`。我一开始写了个「大于 1000 就除以 100」的启发式，结果真实数据里 ¥4.50 返回 `450`，直接显示成 ¥450.00。教训：**不要猜单位，显式转换**。

**② `query-meals` 只给你编码，不给名称和价格**
返回结构是 `data.categories[].meals[].code`，加一点 `tags`，仅此而已。要拿到可读菜单必须再用 `calculate-price` 批量补全。一次别传太多，得分块 + 二分重试。

**③ 套餐改配的定价协议得自己逆向**
套餐组成是 `rounds[].choices[]`，每个 choice 有 `isDefault` 和 `diffPrice`（字符串 `"+ ¥1.5"`）。想算改配后的价格，必须回传**完整**的 `roundList`——每轮都要有，`round` 是数字 id 的**字符串**形式，且只能选真实存在的 code。公式是 `新价 = 套餐价 + Σ(diffPrice × 轮次数量)`，我用真实数据验证过：11450 → 11800 → 11950 → 12300。

**④ 门店前置 + beCode 的坑**
菜单/价格/券类工具都必须先有门店。`beCode` 在到店自取（`beType=1`）时**不能传**，外送/得来速/团餐（2/5/6）时**必须传**，否则报 600048。另外 `query-nearby-stores` 的 `city` 和 `keyword` 必须同时非空，否则 600058。

**⑤ 营养数据是一整段紧凑表格字符串**
`list-nutrition-foods` 返回的是这种格式：
```
[160]{productName,nutritionDescription,energyKj,energyKcal,...}:
  巨无霸,null,2146,513,...
```
而且餐品名和菜单对不上——菜单叫「麦辣鸡翅2块」，营养表叫「麦辣鸡翅-2块」。得做名称归一化。

**⑥ 真实菜单里混着非餐品**
「小食甜品 /其他」类目下混着 ¥14.90 的**按摩捶痒痒挠**，「蘸酱炸鸡」下混着 ¥3 的**蘸酱**。我的团餐推荐器一开始用「预算内取最便宜」，结果给预算 ¥25 的人推了 ¥2 的饼干——约束全满足，但没人会这么点单。后来改成：排除非餐品 → 按餐品等级排序 → 取最接近预算的那份。

**关于测试**
192 个测试，离线模式与线上共用同一条代码路径，`test_demo.py` 专门锁死「演示数据和真实接口行为必须一致」。这样 CI 里不用 Token 也能保证不跑偏。

**四个玩法**：🧘 修行录（成就徽章 + 麦门段位）· 🍱 团餐指挥官（多人需求合成最优团餐）· 🧪 隐藏菜单实验室（重组套餐配方 + 实时核价）· 🔮 每日运势签（今天宜吃啥 + 抽奖吉时）
